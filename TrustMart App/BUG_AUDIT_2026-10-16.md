# TrustMart Android bug audit — 16 October 2026

This review covers the buyer/seller Android application in `TrustMart App`.
The current checkout was inspected directly; several fixes described in the earlier
conversation were absent from these sources. Existing backend, website and moderator
working changes were left in place. The local backend `.env` host list was corrected
as described below; existing host entries were preserved.

## Confirmed bugs and fixes

| Area | Trigger and previous behavior | Fix and code location |
| --- | --- | --- |
| USB backend connection: HTTP 400 | `http://127.0.0.1:8000/api/categories/` returned HTTP 400 / `DisallowedHost`, while the same endpoint through `localhost` returned HTTP 200. The local host list omitted the USB loopback address. | Add `127.0.0.1` to `backend/.env`, line 3 (`ALLOWED_HOSTS`), preserving `localhost` and the existing LAN IP. Trigger the development server's reload. |
| Edit Listing: unsaved draft | Returning from a document picker restarts the screen loader. `loadDetail` clears `detail`, causing `ListingEditor` to leave composition and lose unsaved fields/photos. | Keep the editor mounted with its last matching listing during refresh. `ui/EditListingScreen.kt`, `EditListingScreen`. A new device regression simulates the null-detail interval and verifies the typed title survives. |
| Edit Listing: photo selection | Select new photos, reopen the picker, then cancel: the empty picker result replaced the previous selection. Selected document permissions were also not persisted. | Preserve previous photos on cancellation, deduplicate/limit accepted selections, and request persistent read permission where supported. `ui/EditListingScreen.kt`, picker callback; `data/ClientValidation.kt`, `selectedPhotos`. |
| Product Details: saved indicator | The product heart always used the outline icon, even when the listing was already in the wishlist. | Derive the icon and accessible action label from the saved state. `ui/MarketplaceScreens.kt`, `ListingScreen`. |
| Product Details: seller rating | Open another product, then fail/delay its reviews request: the previous seller's reviews remained visible beside the new product. | Clear reviews when starting a detail load. `AppViewModel.kt`, `loadDetail`. |
| Wishlist / Notifications: false failure | A write succeeded but its following GET failed; the app reported the whole action as failed. Retrying a wishlist toggle could undo the successful action. | Use the existing acknowledgement-before-refresh flow. Mark notifications read locally after acknowledgement and report a refresh failure separately. `AppViewModel.kt`, `toggleWishlist` and `readNotifications`. |
| Session refresh: crash / resource leak | A malformed successful refresh response could throw a runtime exception from an OkHttp worker; refresh failure also left the original 401 response open. | Validate both tokens before storing either, convert invalid responses to `IOException`, and close the original response on refresh failure. Reject foreign-origin requests with `IOException` too. `data/Api.kt`, interceptor/refresh; `data/ClientValidation.kt`, `parseRefreshedTokens`. |

The two integer Compose states flagged for boxing were also changed to `mutableIntStateOf`
in `ui/MarketplaceScreens.kt` and `ui/SellerScreens.kt`.

## Regression coverage

- `ClientValidationTest.kt`: cancellation preserves photos; replacement selection is unique
  and bounded; valid token responses decode; malformed responses always raise `IOException`.
- `ScreenLayoutTest.kt`: product wishlist state changes correctly; an unsaved listing title
  survives the detail reload that happens after returning from the picker.
- Existing action-flow tests cover successful writes followed by failed refreshes.

Device tests use isolated fixtures. They do not submit real purchases, listings, reviews,
messages or moderation decisions. A complete live-account flow and every external document
provider are not covered by these tests.

## Verification results

- Final debug build and lint completed successfully.
- After the configuration reload, `http://127.0.0.1:8000/api/categories/` returned HTTP 200.
- USB port forwarding was restored; the updated app cold-launched successfully and its
  running process had no entries in the Android crash buffer.
- All 34 JVM tests passed, including malformed token/header and photo-selection regressions.
- All 28 Android screen tests passed on Samsung SM-A525F in 48.567 seconds.
- Lint: zero errors and nine dependency-update advisories; none were suppressed.
- The corrected app was installed using `adb install --no-streaming -r`; the initial
  streaming installer stalled and was stopped before retrying.
- Device report: `app/build/reports/device-audit-20261016.txt`.
